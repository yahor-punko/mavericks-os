# Publish Manifest Rules

## Registration procedure

- **Publish-manifest registration** — every new git-tracked file must be classified in `scripts/publish-manifest.json` (ship/exclude) in the same task that creates it; a trailing-slash `exclude` entry (e.g. the `docs/archive/` prefix) classifies every file beneath it, so such files need no per-file registration; see `.claude/rules/docs.md` / `.claude/rules/scripts.md` for the full rule and the `MANIFEST_REGISTRATION_NEEDED` token scope-forbidden roles use. **Pre-spawn registration for docs roles (DR-017):** before spawning a `product-docs` or `technical-writer` task whose brief names a new tracked file at a known path, the Main Agent first commits the task registration, then adds the `ship`/`exclude` entry to `scripts/publish-manifest.json` in the working tree uncommitted, names the path in the brief's `Files to modify` as pre-registered (no token), and lets the entry ride into the booking commit — docs roles commit on the shared checkout and the checker reads the manifest from the working tree, so the pre-commit backstop already sees the entry. The `MANIFEST_REGISTRATION_NEEDED` token remains the fallback for a path not known at spawn; an entry whose file never appears is reported `STALE manifest entries` by the checker at the next commit and is removed then. The Main Agent runs `node scripts/check-publish-manifest.js` before booking `dev_done` on any task that created new files. Per DR-002 (`docs/core/DECISIONS.md`), the Main Agent may apply registration **entries** directly (a state-adjacent classification ledger action) but all other manifest changes go through a developer task. Enforcement is no longer only manual (T-401): `scripts/mavp-manifest-guard.js` gives an advisory creation-time signal via PostToolUse (see `templates/manifest-guard-hook.fragment.json`), and `.claude/hooks/pre-commit` runs `node scripts/check-publish-manifest.js --if-canonical` as a blocking commit-time backstop — both gated to the canonical private repo (inert in the public mirror / adopter repos) via the "every exact `exclude` key is git-tracked" heuristic (`isCanonicalRepo()` in `scripts/check-publish-manifest.js` counts only exact keys, never trailing-slash prefix entries such as `docs/archive/`, and is false when there are none). **A developer brief must never forbid this registration line, and must never route a developer's registration through the `MANIFEST_REGISTRATION_NEEDED` token** — the token exists only for roles whose scope forbids `scripts/` (`product-docs`, `technical-writer`); a developer always self-registers in the same commit, and the pre-commit backstop above makes this mandatory, not a style choice, since a worktree with an unregistered new file cannot produce a commit at all. See DR-007 (`docs/core/DECISIONS.md`) for the incident this closes and the parallel-conflict merge protocol that still applies when two developer tasks' registrations collide.
