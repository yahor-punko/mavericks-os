# Scripts Rules

- Reporting surfaces are read-only operator tools — they report state, they do not modify it. This applies to: dashboard, `--snapshot`, `--agent`/`--watch`, and the validator. The mutating ritual scripts (close-session, new-task, quick-task, update-task, set-status, rename-task, apply-decomposition, merge-task) are explicitly exempt — they intentionally write artifacts as their primary purpose.
- `mavp-operator-lib.js` is shared logic; changes here affect all operator surfaces. Test snapshot and dashboard after any change.
- `mavp-validator.js` parses `## Active Wave` section in BACKLOG.md. If the section heading changes, update the regex in `parseBacklogActiveTasks()`.
- `mavp-operator-agent.js` is the Main Agent's session entry point — keep its JSON output schema stable. Any new fields are additive only.
- Do not add interactive prompts or side effects (file writes) to reporting surfaces (dashboard, snapshot, agent, validator). The mutating ritual scripts listed above are exempt: they may prompt users (close-session interactive mode) and write artifacts by design.
- Node.js only — no external npm dependencies for core operator tooling (dashboard, `--snapshot`, `--agent`/`--watch`, the validator, and all mutating ritual scripts). These must run with zero npm installs. The one exception is `@anthropic-ai/sdk`, declared in `optionalDependencies` in `package.json` and consumed only by `mavp-skill-reflect.js` (`--reflect-skill`) — it is `require()`d lazily inside that script's `main()` function, guarded by try/catch, never at module load. No other script may import it, directly or transitively. `npm install --omit=optional` (or a machine with no `node_modules` at all) must still leave every core command working; only `--reflect-skill` degrades, with a clear "install the optional dependency" error.
- **Publish-manifest registration** — if the repo contains `scripts/publish-manifest.json`, every new git-tracked file must be classified there in the same task: ship for framework content, exclude with a one-line reason for internal material. Roles whose scope excludes `scripts/` must instead emit `MANIFEST_REGISTRATION_NEEDED: <path> -> <ship|exclude> (<reason>)` in their final report so the Main Agent registers it. Developers editing the manifest run `node scripts/check-publish-manifest.js` and quote its output in evidence. See DR-002 (`docs/core/DECISIONS.md`). **Brief authors: a developer brief must never forbid this self-registration line and must never route a developer's registration through the `MANIFEST_REGISTRATION_NEEDED` token above — that token is exclusively for roles whose scope forbids `scripts/`.** `.claude/hooks/pre-commit`'s blocking backstop makes developer self-registration mandatory, not optional: a worktree containing an unclassified new file cannot produce a commit at all, so a brief forbidding the line leaves the task uncommittable. See DR-007 (`docs/core/DECISIONS.md`) for the incident this closes and the parallel-conflict merge protocol (union additive entries, re-run the checker) that still preserves DR-002's original concern where several developer tasks touch the manifest at once.
- **Shipped secret-string discipline (all ship files, not just fixtures)** — this rule covers EVERY git-tracked file classified `ship` in `publish-manifest.json`: source code, code comments, doc prose, and test data/arguments, not only dedicated test-fixture files. A ship file must never embed a literal string the publish secret-scanner detects: private/project repo names, absolute `/Users/` paths, credential/token shapes (AWS keys, PEM blocks, high-entropy secrets), or non-reserved email domains. Three separate tasks tripped this in one wave, and in every case a human read the file and saw nothing wrong — only the assemble+scan gate caught it: a code comment describing the scanner's own detection categories tripped the very category it was describing (T-505); a comment explaining the absolute-path discipline itself contained the matched token, because the scanner matches file text statically and has no concept of "this is prose about the rule, not a violation of it" (T-502); and a private-name string used as a test argument sat as a plain literal in a ship-classified test file, so the assembled tree self-matched on it — worse than a noisy false alarm, since that assertion would have PASSED for the wrong reason, reporting a finding that pointed at the test file rather than at the secret the test had planted (T-513). The remedy is the same in every case: describe the pattern in words, never write the literal shape — even inside a comment, inside doc prose, or inside prose about this very rule. When a test genuinely needs a token matching one of the scanner's categories, construct it at runtime (string concatenation/interpolation) so no contiguous literal substring appears in the file text — the same technique already required for adversarial fixtures below. Reading and grepping the file is NOT the verification step, however careful — the only test that counts is running the gate: `node scripts/mavp-publish-assemble.js <tmpdir>` then `node scripts/mavp-publish-scan.js <tmpdir> --private-names "<comma-separated-fake-placeholder-names>"`; zero findings is the only passing result.

  Adversarial fixtures written specifically to exercise the scanner's detection must do one of two things: (a) construct the detectable string at runtime via string concatenation/interpolation so no literal detectable substring appears in the file text (the scanner matches file text statically, not runtime values), or (b) live in a file classified `exclude` in `publish-manifest.json` with a one-line reason. For dummy email addresses, use only the RFC 2606 / RFC 6761 reserved example domains (`example.com`, `example.net`, `example.org`) or the reserved TLDs `.invalid`, `.test`, `.example`, `.localhost` — these are allowlisted by the scanner. Never bake a private project name into a shipped file; parameterize it (e.g. via argv, a placeholder, or a config value) instead.

- **Reserved shapes (bounded, not universal)** — the lesson above generalizes: a static matcher keys on a literal string sitting at a specific position (contiguous substring anywhere, for the scanner above; column zero of a line, for the two matchers below), and prose that reproduces that exact position gets caught by the matcher it is merely describing. The rule is deliberately BOUNDED to the shapes enumerated here — a universal "never write a literal that any static matcher detects" is unfollowable, because an author cannot enumerate matchers they do not know exist, and an unfollowable rule trains people to ignore rules. Enumerated shapes and remedies:
  - **Publish-scanner categories** (private/project repo names, absolute `/Users/` paths, credential/token shapes, non-reserved email domains) — see the shipped secret-string discipline clause above for the full detail and remedy.
  - **Line-initial task-heading shape in `BACKLOG.md`/`TASK_STATUS.md`** (a line beginning with `###` followed by `T-` and digits, e.g. as scanned by `getNextTaskId()`'s anchored `/^###\s+T-(\d+)/gm` in `mavp-operator-lib.js` — see the citation clause in `.claude/rules/backlog.md`). Remedy: describe the shape in words, or cite an example task ID mid-line and/or backticked (never as the first characters of a line) — a citation like a backticked, mid-sentence `T-900` example is safe; the same digits typed as the literal first four characters of a line in one of the two artifacts, even inside a fenced code block, is not.
  - **Line-initial skip token in test output** (`SKIP_TOKEN` in `scripts/run-tests.js`, currently the literal `[SKIP]`, matched by `extractSkipLines()` when it is the leading text of a printed line). Remedy: describe the token in words in prose, or construct it at runtime when a test genuinely needs to print it, rather than emitting it as literal leading text on a line.

  This list is extended whenever a new static matcher ships whose detection key is a position-sensitive literal (not merely "any string that looks like X" — those already covered by the publish-scanner category above). Adding a shape here is a doc-only edit; it does not require re-litigating the boundedness rule itself.
